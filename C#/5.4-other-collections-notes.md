# 🟦 C# 5.4 — Other Collections

> **Revision status:** ✅ Strong / Recalled

In addition to `List<T>` and `Dictionary<TKey, TValue>`, C# provides several specialized collections for different behaviors and performance needs. This phase focuses on four important ones:

- `HashSet<T>`
- `Queue<T>`
- `Stack<T>`
- `LinkedList<T>`

Each collection is designed around a specific access pattern and trade-off.

---

## 1. HashSet<T>

### 1.1 What is HashSet<T>?
`HashSet<T>` stores **unique elements**. It does not allow duplicates according to its equality rules.

```csharp
HashSet<int> numbers = new();

numbers.Add(10);
numbers.Add(20);
numbers.Add(10);
numbers.Add(30);

Console.WriteLine(numbers.Count); // 3
```

Only `10`, `20`, and `30` are stored.

### 1.2 Why does HashSet<T> exist?
A `List<T>` permits duplicate values. Sometimes, however, an application needs to maintain a collection of unique items and perform membership checks efficiently.

Examples:

- Unique user IDs
- Unique product codes
- Tracking visited nodes in a graph
- Tracking permissions or selected categories

### 1.3 Important methods

| Method | Purpose |
|---|---|
| `Add(item)` | Adds an element if an equivalent element does not already exist |
| `Contains(item)` | Checks whether an element exists |
| `Remove(item)` | Removes an element |
| `Clear()` | Removes all elements |
| `UnionWith(other)` | Keeps elements from both sets |
| `IntersectWith(other)` | Keeps only common elements |
| `ExceptWith(other)` | Removes elements present in the other set |

`Add()` returns `true` if the element was added and `false` if an equivalent element already exists.

```csharp
HashSet<int> ids = new();

Console.WriteLine(ids.Add(101)); // True
Console.WriteLine(ids.Add(102)); // True
Console.WriteLine(ids.Add(101)); // False
```

### 1.4 Hashing and equality
A `HashSet<T>` uses hashing to help locate elements and equality comparisons to determine whether elements are equivalent.

- `GetHashCode()` produces an integer hash code
- `Equals()` determines whether two objects are equal according to their equality implementation
- Different objects can have the same hash code; this is called a hash collision
- A matching hash code does not automatically mean two objects are equal

**Important contract:** Equal objects must have equal hash codes. The reverse is not required.

#### Example with a custom class

```csharp
class Employee
{
    public int Id { get; set; }
}

HashSet<Employee> employees = new();

employees.Add(new Employee { Id = 101 });
employees.Add(new Employee { Id = 101 });

Console.WriteLine(employees.Count); // 2
```

A normal class uses reference equality by default. These are two separate instances, so both can be stored.

If uniqueness should depend on `Id`, implement compatible equality and hashing:

```csharp
class Employee
{
    public int Id { get; set; }

    public override bool Equals(object? obj)
    {
        return obj is Employee other && Id == other.Id;
    }

    public override int GetHashCode()
    {
        return Id.GetHashCode();
    }
}
```

Now two employees with the same ID are considered equal by this implementation.

Avoid changing fields or properties used for equality and hashing while an object is in a hash set. Such changes can interfere with lookup and removal.

### 1.5 Set operations

```csharp
HashSet<int> a = new() { 10, 20, 30 };
HashSet<int> b = new() { 20, 30, 40 };
```

- `a.UnionWith(b)` produces `{10, 20, 30, 40}`
- `a.IntersectWith(b)` produces `{20, 30}`
- `a.ExceptWith(b)` produces `{10}`

These methods modify the receiving set. They do not automatically create a new set.

### 1.6 Performance

- `Contains()` — O(1) average, O(n) worst case
- `Add()` — O(1) average, O(n) worst case
- `Remove()` — O(1) average, O(n) worst case

These are typical complexity descriptions; actual performance depends on implementation details and hashing behavior.

A `List<T>.Contains()` operation is O(n), so a hash set can be more suitable when checking membership repeatedly in a large collection.

### 1.7 Common misconceptions

- A hash set is not guaranteed to be sorted
- Duplicate prevention depends on equality rules, not just matching property values
- Equal hash codes do not prove equality
- A hash set is not the best choice when duplicates or index-based access are required
- Set operations such as `IntersectWith()` modify the existing set

## 2. Queue<T>

### 2.1 What is Queue<T>?
`Queue<T>` follows **FIFO — First In, First Out**.

The first item added is the first item removed.

```csharp
Queue<string> tasks = new();

tasks.Enqueue("Email");
tasks.Enqueue("Report");
tasks.Enqueue("Backup");

Console.WriteLine(tasks.Dequeue()); // Email
Console.WriteLine(tasks.Dequeue()); // Report
```

### 2.2 Why does Queue<T> exist?
Applications frequently need to process work in arrival order.

Examples:

- Processing uploaded files in order
- Handling requests waiting for processing
- Managing print jobs
- Processing messages or background tasks

A queue allows one part of an application to add work while another part processes it.

### 2.3 Important methods

| Method | Purpose |
|---|---|
| `Enqueue(item)` | Adds an item to the back |
| `Dequeue()` | Removes and returns the front item |
| `Peek()` | Reads the front item without removing it |
| `TryDequeue(out item)` | Removes an item if available; otherwise returns `false` |
| `TryPeek(out item)` | Reads the front item if available; otherwise returns `false` |
| `Contains(item)` | Checks whether an item exists |
| `Clear()` | Removes all items |
| `Count` | Gets the number of elements |

#### Example

```csharp
Queue<int> numbers = new();

numbers.Enqueue(10);
numbers.Enqueue(20);
numbers.Enqueue(30);

Console.WriteLine(numbers.Peek());    // 10
Console.WriteLine(numbers.Dequeue()); // 10
Console.WriteLine(numbers.Count);     // 2
```

`Peek()` leaves `10` in the queue. `Dequeue()` removes it.

### 2.4 Handling an empty queue
`Dequeue()` and `Peek()` throw `InvalidOperationException` if the queue is empty.

Use `TryDequeue()` when an empty queue is an expected possibility:

```csharp
Queue<int> numbers = new();

if (numbers.TryDequeue(out int value))
{
    Console.WriteLine($"Removed: {value}");
}
else
{
    Console.WriteLine("Queue is empty");
}
```

If an element exists, `TryDequeue()` removes it, assigns it to the `out` variable, and returns `true`. Otherwise, it returns `false`.

`TryPeek()` behaves similarly but does not remove the element.

### 2.5 Performance
For the standard .NET `Queue<T>` implementation:

- `Enqueue()` — O(1) amortized
- `Dequeue()` — O(1)
- `Peek()` — O(1)
- `Contains()` — O(n)

Amortized O(1) means adding is constant time on average over a sequence of operations, even though an individual addition may take longer when the internal storage must grow.

### 2.6 Common misconceptions

- `Peek()` does not remove an item
- `Dequeue()` removes the oldest remaining item
- An empty queue does not make `Dequeue()` return a default value; it throws an exception
- `TryDequeue()` removes the item when successful
- An in-memory queue does not automatically provide persistence, retry handling, or thread-safe coordination

## 3. Stack<T>

### 3.1 What is Stack<T>?
`Stack<T>` follows **LIFO — Last In, First Out**.

The last item added is the first item removed.

Think of a stack of plates: the last plate placed on top is the first one taken off.

```csharp
Stack<string> actions = new();

actions.Push("Type text");
actions.Push("Make text bold");
actions.Push("Change font size");

Console.WriteLine(actions.Pop()); // Change font size
Console.WriteLine(actions.Pop()); // Make text bold
```

### 3.2 Why does Stack<T> exist?
Some problems naturally require reversing the order of recent operations.

Examples:

- Undo functionality
- Browser navigation history, in some designs
- Tracking method calls and execution contexts
- Parsing expressions
- Depth-first search and backtracking algorithms

A stack makes it easy to work with the most recently added element first.

### 3.3 Important methods

| Method | Purpose |
|---|---|
| `Push(item)` | Adds an item to the top |
| `Pop()` | Removes and returns the top item |
| `Peek()` | Reads the top item without removing it |
| `TryPop(out item)` | Removes an item if available; otherwise returns `false` |
| `TryPeek(out item)` | Reads the top item if available; otherwise returns `false` |
| `Contains(item)` | Checks whether an item exists |
| `Clear()` | Removes all items |
| `Count` | Gets the number of elements |

#### Example

```csharp
Stack<int> numbers = new();

numbers.Push(10);
numbers.Push(20);
numbers.Push(30);

Console.WriteLine(numbers.Peek()); // 30
Console.WriteLine(numbers.Pop());  // 30
Console.WriteLine(numbers.Count);  // 2
```

The top item is `30` because it was pushed last.

### 3.4 Handling an empty stack
`Pop()` and `Peek()` throw `InvalidOperationException` when the stack is empty.

Use `TryPop()` when an empty stack is an expected situation:

```csharp
Stack<int> numbers = new();

if (numbers.TryPop(out int value))
{
    Console.WriteLine($"Removed: {value}");
}
else
{
    Console.WriteLine("Stack is empty");
}
```

If an element exists, `TryPop()` removes the top element and assigns it to `value`. It returns `true`. If empty, it returns `false`.

`TryPeek()` reads the top element without removing it and returns `false` if the stack is empty.

### 3.5 Performance
For the standard .NET `Stack<T>` implementation:

- `Push()` — O(1) amortized
- `Pop()` — O(1)
- `Peek()` — O(1)
- `Contains()` — O(n)

Like a queue, a stack uses internal storage that can occasionally grow, making an individual push more expensive even though its amortized cost is O(1).

### 3.6 Queue vs. Stack

| Feature | `Queue<T>` | `Stack<T>` |
|---|---|---|
| Order | FIFO | LIFO |
| Add | `Enqueue()` | `Push()` |
| Remove | `Dequeue()` | `Pop()` |
| Inspect | `Peek()` | `Peek()` |
| First removed | Oldest item | Newest item |
| Example | Arrival-ordered jobs | Undoing recent actions |

### 3.7 Common misconceptions

- A stack is not automatically sorted
- `Peek()` reads the top item without removing it
- `Pop()` on an empty stack throws `InvalidOperationException`
- `TryPop()` removes an element when successful
- A stack is not a substitute for a queue when work must be processed in arrival order

## 4. LinkedList<T>

### 4.1 What is LinkedList<T>?
`LinkedList<T>` is a **doubly linked list** in .NET.

Instead of storing elements in one contiguous array-like structure, it stores elements in nodes. Each node contains a value and links to the previous and next nodes.

Conceptually:

```text
null ← [10] ⇄ [20] ⇄ [30] → null
```

Each node can move forward or backward through its links.

In C#, a `LinkedList<T>` is not accessed by an integer index like a `List<T>`.

### 4.2 Why does LinkedList<T> exist?
Some applications frequently insert or remove elements at known positions in a sequence. A linked list can perform these operations efficiently when you already have the relevant node.

Examples:

- Maintaining a sequence of items where nodes are frequently inserted or removed
- Implementing certain navigation or scheduling structures
- Representing sequences where node references are already available

However, a linked list is not automatically faster than a `List<T>`. Finding a node still requires traversal.

### 4.3 Creating a LinkedList<T>

```csharp
LinkedList<int> numbers = new();

numbers.AddLast(10);
numbers.AddLast(20);
numbers.AddLast(30);
```

The list is:

```text
10 ⇄ 20 ⇄ 30
```

You can also add at the beginning:

```csharp
numbers.AddFirst(5);
```

Now the list is:

```text
5 ⇄ 10 ⇄ 20 ⇄ 30
```

### 4.4 Important methods

| Method | Purpose |
|---|---|
| `AddFirst(value)` | Adds a new node at the beginning |
| `AddLast(value)` | Adds a new node at the end |
| `AddBefore(node, value)` | Adds a node before a specified node |
| `AddAfter(node, value)` | Adds a node after a specified node |
| `RemoveFirst()` | Removes the first node |
| `RemoveLast()` | Removes the last node |
| `Remove(value)` | Removes the first matching value |
| `Remove(node)` | Removes the specified node |
| `Find(value)` | Finds the first matching node |
| `FindLast(value)` | Finds the last matching node |
| `Clear()` | Removes all nodes |
| `First` | Gets the first node |
| `Last` | Gets the last node |
| `Count` | Gets the number of nodes |

#### Example: insert after a node

```csharp
LinkedList<int> numbers = new();

numbers.AddLast(10);
numbers.AddLast(20);
numbers.AddLast(30);

LinkedListNode<int>? node = numbers.Find(20);

if (node != null)
{
    numbers.AddAfter(node, 25);
}
```

The resulting list is:

```text
10 ⇄ 20 ⇄ 25 ⇄ 30
```

The call to `Find(20)` traverses the list to locate the node. Once the node is found, insertion after it is efficient.

### 4.5 Understanding nodes
A linked list stores values in `LinkedListNode<T>` objects.

A node exposes:

- `Value` — the stored value
- `Next` — the next node
- `Previous` — the previous node
- `List` — the list to which the node belongs

Example:

```csharp
LinkedList<int> numbers = new();

numbers.AddLast(10);
numbers.AddLast(20);
numbers.AddLast(30);

LinkedListNode<int>? current = numbers.First;

while (current != null)
{
    Console.WriteLine(current.Value);
    current = current.Next;
}
```

Output:

```text
10
20
30
```

This is traversal: starting at the first node and following `Next` until it becomes `null`.

### 4.6 Performance and trade-offs

| Operation | Typical complexity |
|---|---|
| Access `First` or `Last` | O(1) |
| Add first or last | O(1) |
| Remove first or last | O(1) |
| Insert before/after a known node | O(1) |
| Find a value | O(n) |
| Access an element by position | O(n) |

Removing a known node is O(1), but finding that node by value is O(n). The total operation includes both costs if you must search first.

#### LinkedList<T> vs. List<T>

| Feature | `List<T>` | `LinkedList<T>` |
|---|---|---|
| Internal structure | Dynamic array | Doubly linked nodes |
| Access by index | O(1) | No indexer; traversal required |
| Find a value | O(n) | O(n) |
| Add at end | Amortized O(1) | O(1) |
| Insert at a known position | Elements may need shifting | O(1) if you already have the node |
| Memory overhead | Usually lower | Higher due to node objects and links |
| Cache locality | Generally better | Generally worse |

For most ordinary application lists, `List<T>` is a good default. Choose `LinkedList<T>` when its node-based insertion/removal behavior is a real advantage.

### 4.7 Common misconceptions

- A linked list is not automatically faster than a list
- `LinkedList<T>` has no integer indexer such as `numbers[2]`
- Finding a value in a linked list is O(n)
- Insertion is O(1) only when the relevant node is already known
- A doubly linked list requires additional memory for node links and node objects
- `LinkedList<T>` does not automatically sort elements

## 5. Compare all four collections

| Requirement | Suitable collection |
|---|---|
| Store unique values and check membership | `HashSet<T>` |
| Process items in arrival order | `Queue<T>` |
| Process the most recent item first | `Stack<T>` |
| Insert/remove around known nodes | `LinkedList<T>` |
| Need index-based access and duplicates | Usually `List<T>` |
| Look up values by unique keys | `Dictionary<TKey, TValue>` |

### Decision examples

**Scenario 1:** Track user IDs already processed.

Use `HashSet<int>` because duplicate IDs should not be added, and membership checks are frequent.

**Scenario 2:** Process files in the order uploaded.

Use `Queue<string>` because the oldest item should be processed first.

**Scenario 3:** Undo the most recent editing operation.

Use `Stack<EditAction>` because the most recent action should be reversed first.

**Scenario 4:** Frequently insert or remove items immediately before or after known nodes.

Consider `LinkedList<T>`, especially when you already hold the relevant node references.

## 6. Understanding questions with answers

### Q1. Can a HashSet contain two unequal objects with the same hash code?
Yes. A hash collision does not establish equality.

### Q2. What does `HashSet<T>.Add()` return?
`true` if the element is added, and `false` if an equivalent element already exists.

### Q3. What does FIFO mean?
First In, First Out. A queue removes the oldest remaining element first.

### Q4. What is the difference between `Dequeue()` and `Peek()`?
`Dequeue()` removes and returns the front element. `Peek()` reads it without removing it.

### Q5. Why use `TryDequeue()`?
It allows the program to handle an empty queue without relying on an exception for normal control flow.

### Q6. What does LIFO mean?
Last In, First Out. A stack removes the newest element first.

### Q7. What is the difference between `Pop()` and `Peek()` on a stack?
`Pop()` removes and returns the top element. `Peek()` reads it without removing it.

### Q8. Why does `LinkedList<T>` use nodes?
Each node stores a value and links to neighboring nodes, supporting efficient insertion and removal around a known node.

### Q9. Is finding a value in a `LinkedList<T>` O(1)?
No. Finding a value is O(n), because the list may need to be traversed.

### Q10. Is `LinkedList<T>` always faster than `List<T>` for insertion?
No. It is efficient when the relevant node is already known. Searching for the node can take O(n), and a `List<T>` may be better for many ordinary workloads.

## 7. Coding exercises
These are the exercises to use for practice. Each collection has its own exercise.

### Exercise A: HashSet<T>

1. Create a `HashSet<int>`.
2. Add `10`, `20`, `30`, and `20`.
3. Print `Count`.
4. Check whether `20` exists.
5. Attempt to add `20` again and print the returned Boolean.
6. Remove `10` and print the final count.

Expected checkpoints: initial count `3`; `Contains(20)` is `true`; duplicate `Add(20)` returns `false`; final count `2`.

### Exercise B: Queue<T>

1. Create a `Queue<string>`.
2. Enqueue `"Email"`, `"Report"`, and `"Backup"`.
3. Print the next item with `Peek()`.
4. Dequeue and print two items.
5. Print the remaining count.

Expected output:

```text
Email
Email
Report
1
```

### Exercise C: Stack<T>

1. Create a `Stack<string>`.
2. Push `"Type"`, `"Bold"`, and `"Resize"`.
3. Print the top element using `Peek()`.
4. Pop and print two elements.
5. Print the remaining count.

Expected output:

```text
Resize
Resize
Bold
1
```

### Exercise D: LinkedList<T>

1. Create a `LinkedList<int>`.
2. Add `10`, `20`, and `30` using `AddLast()`.
3. Find the node containing `20`.
4. If found, insert `25` after it.
5. Traverse the list and print each value.
6. Remove the first node and print the count.

Expected traversal output before removal:

```text
10
20
25
30
```

The count after removing the first node is `3`.

## 9. Final revision summary

- **HashSet<T>:** unique elements, equality rules, hash-based membership checks
- **Queue<T>:** FIFO, `Enqueue()`, `Dequeue()`, `Peek()`
- **Stack<T>:** LIFO, `Push()`, `Pop()`, `Peek()`
- **LinkedList<T>:** doubly linked nodes, efficient insertion/removal around known nodes, linear traversal

Remember that collection choice is not just about syntax. It is about the operations your application performs most often, the required ordering, equality rules, and the performance trade-offs.
