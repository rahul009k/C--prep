# 🟦 C# 1.2 — Variables & Data Types

> **Revision status:** 📝 Not started

This note explains how C# stores values, checks types, handles references, and represents missing values.

---

## 🧭 1. Variables and Types

A **variable** is a named value holder.

```csharp
int age = 25;
```

- `int` → type
- `age` → variable
- `25` → value

The **type** tells C# what kind of data the variable can hold and which operations are allowed.

C# is **statically typed**, so the compiler knows the type during compilation.

---

## 🔒 2. Constants

A `const` represents a value that cannot be changed after declaration.

```csharp
const int MaxUsers = 100;
```

This is not allowed:

```csharp
MaxUsers = 200; // Error
```

Normal variables can be changed:

```csharp
int maxUsers = 100;
maxUsers = 200;
```

---

## 📦 3. Value Types

Common value types include:

```text
int
double
bool
char
struct
enum
```

When a value type is assigned to another variable, the **value is copied**.

```csharp
int a = 10;
int b = a;

b = 20;
```

Result:

```text
a = 10
b = 20
```

Changing `b` does not affect `a`.

### 💡 Remember

> **Value type → copying copies the value.**

---

## 🔗 4. Reference Types

Common reference types include:

```text
class
string
array
delegate
```

A reference-type variable holds a **reference to an object**.

```csharp
Person p1 = new Person();
Person p2 = p1;
```

Both `p1` and `p2` refer to the same object.

```csharp
p2.Name = "John";
```

`p1.Name` is also `"John"` because both references point to the same object.

### 💡 Remember

> **Reference type → copying copies the reference.**

### Important parameter rule

C# parameters are passed **by value by default**.

For a reference type, the **reference itself is copied**.

```csharp
void Change(Person person)
{
    person.Name = "John";
}
```

The copied reference still points to the same object, so the object's data can be changed.

However, reassigning the local parameter does not change the caller's variable:

```csharp
void Change(Person person)
{
    person = new Person();
}
```

Only the local copy of the reference was reassigned.

---

## 🧠 5. Stack vs Heap: Important Clarification

Do not memorize this oversimplification:

```text
Value types = stack
Reference types = heap
```

The important C# distinction is:

```text
Value type     → copy the value
Reference type → copy the reference
```

A reference-type object can also contain value-type fields:

```csharp
class Person
{
    public int Age;
}
```

`Person` is a reference type, while `Age` is a value type.

For now, do not worry about the exact memory location. Memory management is covered later.

---

## 🔍 6. `var`

`var` means the compiler **infers the type at compile time**.

```csharp
var age = 25;
```

The compiler treats `age` as an `int`:

```csharp
int age = 25;
```

This is not allowed:

```csharp
var age = 25;
age = "Hello"; // Error
```

### 💡 Remember

> **`var` is still statically typed. It is not `dynamic`.**

---

## 🧱 7. `object`

`object` is the base type from which all C# types ultimately derive.

```csharp
object value = 10;
value = "Hello";
```

This is valid because the variable's type remains `object`; the value it currently references can change.

However:

```csharp
object value = "Hello";

Console.WriteLine(value.Length); // Error
```

The compiler only knows `value` as `object`. To access members specific to `string`, use a cast:

```csharp
Console.WriteLine(((string)value).Length);
```

### 💡 Remember

> **`object` → the compiler sees the variable as `object`.**

---

## ⚡ 8. `dynamic`

`dynamic` tells C# to defer certain member and binding checks until **runtime**.

```csharp
dynamic value = 10;

Console.WriteLine(value.Length);
```

This compiles, but at runtime C# discovers that `int` does not have a `Length` member. A `RuntimeBinderException` occurs.

### Comparison

| Keyword | What happens | When is the member checked? |
| --- | --- | --- |
| `var` | Type is inferred | Compile time |
| `object` | Variable is viewed as `object` | Compile time |
| `dynamic` | Binding can be resolved dynamically | Runtime |

### 💡 Remember

> **`dynamic` can move some errors from compile time to runtime.**

---

## 🚫 9. `null`

`null` means there is no object or reference value.

```csharp
string name = null;
```

Compare these values:

```csharp
string a = null;  // No reference/object
string b = "";   // Empty string, 0 characters
string c = " ";  // One space character
```

Therefore:

```text
null ≠ ""
```

---

## ❔ 10. Nullable Value Types

Normal value types cannot contain `null`:

```csharp
int age = null; // Error
```

Using `?` makes the value type nullable:

```csharp
int? age = null;
```

This means:

```text
int? → can contain an int or null
```

---

## 🎯 Most Important Things to Remember

```text
Variable → named value holder

Type → tells C# what kind of value it is

Value type → copying copies the value

Reference type → copying copies the reference

var → compile-time type inference

object → compiler sees object

dynamic → binding can happen at runtime

null → absence of a reference/value

int? → nullable int

const → cannot be changed
```

### 🧠 One-line mental model

> **Value types copy values; reference types copy references.**

That is the most important concept from this section.
