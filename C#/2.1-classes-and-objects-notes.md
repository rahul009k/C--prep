# C# 2.1 - Classes & Objects

> **Revision status:** Strong / Recalled

A class defines what an object looks like and can do. An object is an instance created from that class.

---

## 1. Class

A **class** is a blueprint or type definition used to create objects. It can contain fields, properties, methods, constructors, and static members.

```csharp
class Person
{
    public string Name;
    public int Age;

    public void Introduce()
    {
        Console.WriteLine($"Hi, I am {Name}");
    }
}
```

The class is the definition; it does not represent one particular person.

---

## 2. Object

An **object** is an instance of a class.

```csharp
Person p1 = new Person();
Person p2 = new Person();

p1.Name = "Rahul";
p2.Name = "John";
```

This creates two different objects, each with its own instance state.

A reference assignment does not create another object:

```csharp
Person p1 = new Person();
Person p2 = p1;

p1.Name = "Rahul";
Console.WriteLine(p2.Name); // Rahul
```

Both variables refer to the same object.

```text
Class  -> definition or blueprint
Object -> actual instance
```

---

## 3. Fields

A **field** is a variable declared directly inside a class. Fields commonly represent stored object state.

```csharp
class Person
{
    public string Name;
    public int Age;
}
```

Each object gets its own copy of an instance field:

```csharp
Person p1 = new Person();
Person p2 = new Person();

p1.Name = "Rahul";
p2.Name = "John";
```

Here, `p1.Name` and `p2.Name` contain different values.

---

## 4. Properties

A **property** provides controlled access to data.

```csharp
class Person
{
    public string Name { get; set; }
    public int Age { get; set; }
}
```

A field stores data directly:

```csharp
public int Age;
```

A property provides access through accessors:

```csharp
public int Age { get; set; }
```

Properties are commonly preferred because they can restrict access and contain validation logic.

### Property with validation

```csharp
class Person
{
    private int _age;

    public int Age
    {
        get
        {
            return _age;
        }
        set
        {
            if (value >= 0)
                _age = value;
        }
    }
}
```

`value` represents the value being assigned to the property.

```csharp
person.Age = 30;
```

### Auto-property

```csharp
public string Name { get; set; }
```

C# provides the backing storage automatically.

### Read-only property

```csharp
public int Age { get; }
```

There is no setter exposed.

### Private setter

```csharp
class BankAccount
{
    public decimal Balance { get; private set; }

    public void Deposit(decimal amount)
    {
        Balance += amount;
    }
}
```

Other code can read `account.Balance`, but only the class can modify it through the private setter.

---

## 5. Methods

Methods represent the behavior or actions of an object.

```csharp
class BankAccount
{
    public decimal Balance { get; private set; }

    public void Deposit(decimal amount)
    {
        Balance += amount;
    }

    public bool CanWithdraw(decimal amount)
    {
        return amount <= Balance;
    }
}
```

```text
State    -> Balance
Behavior -> Deposit(), CanWithdraw()
```

An object combines state and behavior.

---

## 6. Constructors

A **constructor** is a special member that runs when an object is created.

```csharp
class Person
{
    public string Name { get; }

    public Person()
    {
        Name = "Unknown";
    }
}

Person person = new Person();
```

Constructor rules:

- It has the same name as the class.
- It has no return type.
- It runs when an object is created.
- It can accept parameters.
- It can be overloaded.

```csharp
public Person()
{
}
```

This is a constructor. The following is a method because `void` is a return type:

```csharp
public void Person()
{
}
```

---

## 7. Why Constructors Are Useful

Constructors are useful when an object needs required information to be initialized correctly.

```csharp
class BankAccount
{
    public string AccountNumber { get; }
    public decimal Balance { get; }

    public BankAccount(string accountNumber, decimal balance)
    {
        AccountNumber = accountNumber;
        Balance = balance;
    }
}

var account = new BankAccount("ACC1001", 5000);
```

When no parameterless constructor exists, this is not allowed:

```csharp
var account = new BankAccount();
```

Constructors can also validate input:

```csharp
public BankAccount(string accountNumber, decimal balance)
{
    if (string.IsNullOrWhiteSpace(accountNumber))
        throw new ArgumentException("Account number is required.");

    if (balance < 0)
        throw new ArgumentException("Balance cannot be negative.");

    AccountNumber = accountNumber;
    Balance = balance;
}
```

```text
Require data -> validate data -> initialize object
```

---

## 8. Types of Constructors

### Parameterless constructor

```csharp
public Person()
{
}

var person = new Person();
```

### Parameterized constructor

```csharp
public Person(string name, int age)
{
    Name = name;
    Age = age;
}

var person = new Person("Rahul", 30);
```

### Constructor overloading

A class can have multiple constructors with different parameter signatures.

```csharp
class Person
{
    public Person()
    {
    }

    public Person(string name)
    {
    }

    public Person(string name, int age)
    {
    }
}
```

C# selects a constructor based on the arguments:

```csharp
new Person();
new Person("Rahul");
new Person("Rahul", 30);
```

A constructor signature is determined by the number of parameters, parameter types, and parameter order. Parameter names do not distinguish overloads.

```csharp
Person(string name)
Person(string city) // Invalid: both have the signature Person(string)
```

These are valid overloads because their parameter types differ:

```csharp
Person(string name)
Person(int age)
```

## 9. Static Constructor

A static constructor initializes static state for a type.

```csharp
class Configuration
{
    public static string Environment;

    static Configuration()
    {
        Environment = "Production";
    }
}
```

A static constructor:

- Uses `static`.
- Has no parameters.
- Has no access modifier.
- Runs automatically.
- Is used to initialize static state.

```text
Instance constructor -> initializes an object
Static constructor   -> initializes type-level state
```

---

## 10. Copy Constructor

A copy constructor is a constructor pattern in which one object initializes another object. C# does not have a special `copy` keyword.

```csharp
class Person
{
    public string Name { get; }
    public int Age { get; }

    public Person(string name, int age)
    {
        Name = name;
        Age = age;
    }

    public Person(Person other)
    {
        Name = other.Name;
        Age = other.Age;
    }
}

Person p1 = new Person("Rahul", 30);
Person p2 = new Person(p1);
```

`p2` is a new object initialized from `p1`.

This is different from reference copying:

```csharp
Person p2 = p1;          // Same object
Person p3 = new Person(p1); // New object
```

## 11. Object Initializers

An object initializer assigns properties while creating an object.

Without an initializer:

```csharp
var person = new Person();
person.Name = "Rahul";
person.Age = 30;
```

With an initializer:

```csharp
var person = new Person
{
    Name = "Rahul",
    Age = 30
};
```

Object initializers make multiple property assignments concise and readable.

### Object initializers and constructors

An object initializer does not replace the constructor. The constructor runs first, then the initializer assigns properties.

```csharp
var employee = new Employee("Rahul")
{
    Age = 30
};
```

Conceptually:

```text
new Employee("Rahul")
        -> constructor
        -> object created
        -> object initializer
        -> additional properties assigned
```

## 12. Static Members

An instance member belongs to an object. A static member belongs to the type or class.

```csharp
class Counter
{
    public int InstanceCount;
    public static int StaticCount;
}

var c1 = new Counter();
var c2 = new Counter();

c1.InstanceCount++;
c2.InstanceCount++;

Counter.StaticCount++;
Counter.StaticCount++;
```

The result is:

```text
c1.InstanceCount     -> 1
c2.InstanceCount     -> 1
Counter.StaticCount  -> 2
```

```text
Instance member -> one copy per object
Static member   -> one shared member for the type
```

### Static methods

```csharp
class MathHelper
{
    public static int Add(int a, int b)
    {
        return a + b;
    }
}

int result = MathHelper.Add(10, 20);
```

No object is required to call a static method. `Math.Max(...)` and `int.Parse(...)` use this pattern.

---

## 13. Static vs Instance Access

A static method can directly access static members:

```csharp
class Counter
{
    public static int StaticCount;

    public static void Show()
    {
        Console.WriteLine(StaticCount);
    }
}
```

A static method cannot directly access an instance member because it does not know which object should be used:

```csharp
class Counter
{
    public int InstanceCount;

    public static void Show()
    {
        Console.WriteLine(InstanceCount); // Invalid
    }
}
```

An object or reference can be provided explicitly:

```csharp
public static void Show(Counter counter)
{
    Console.WriteLine(counter.InstanceCount);
}
```

```text
Static member  -> can directly access static members
Instance member -> can access instance and static members
```

## 14. `this` Keyword

`this` refers to the current object instance.

```csharp
class Person
{
    public string Name { get; set; }

    public void ShowName()
    {
        Console.WriteLine(this.Name);
    }
}
```

If `ShowName()` is called on an object named `p`, then `this` refers to `p`.

### `this` in constructors

A common use is distinguishing a field or property from a parameter with the same name.

```csharp
class Employee
{
    public string Name;

    public Employee(string name)
    {
        this.Name = name;
    }
}
```

`this.Name` belongs to the current `Employee` object, while `name` is the constructor parameter.

### Passing `this`

```csharp
class Person
{
    public void SendToLogger()
    {
        Logger.Log(this);
    }
}
```

Here, `this` passes the current `Person` object.

## 15. `base` Keyword

`base` is used inside a derived class to access members of its base class.

```csharp
class Person
{
    public virtual void Introduce()
    {
        Console.WriteLine("I am a person");
    }
}

class Employee : Person
{
    public override void Introduce()
    {
        base.Introduce();
        Console.WriteLine("I am an employee");
    }
}
```

`base.Introduce()` calls the base class implementation before the derived behavior.

### `base` with constructors

`base` can call a base class constructor.

```csharp
class Person
{
    public string Name { get; }

    public Person(string name)
    {
        Name = name;
    }
}

class Employee : Person
{
    public int EmployeeId { get; }

    public Employee(string name, int employeeId)
        : base(name)
    {
        EmployeeId = employeeId;
    }
}
```

Constructor execution order is:

```text
Employee("Rahul", 101)
        -> Person("Rahul")       // base constructor
        -> Employee constructor
        -> EmployeeId = 101
```

The base constructor runs first so the base portion of the object is initialized before the derived portion.

---

## 16. `this` vs `base`

| Keyword | Meaning | Example |
| --- | --- | --- |
| `this` | Current object or current class instance | `this.Name` |
| `base` | Base class or parent class | `base.Introduce()` |

```text
this -> current object
base -> parent/base class
```

## Real-World Example

```csharp
class BankAccount
{
    public string AccountNumber { get; }
    public decimal Balance { get; private set; }

    public BankAccount(string accountNumber, decimal balance)
    {
        AccountNumber = accountNumber;
        Balance = balance;
    }

    public void Deposit(decimal amount)
    {
        Balance += amount;
    }
}
```

In this example:

```text
Class            -> BankAccount
Object           -> individual bank account
Properties       -> AccountNumber and Balance
Constructor      -> establishes initial account state
Method           -> Deposit()
private set      -> prevents outside code from directly changing Balance
```

## Common Misconceptions

### Class and object are the same

No. A class is a definition or blueprint; an object is an instance of that class.

### `Person p2 = p1` creates a new object

No. It copies the reference, so both variables refer to the same object.

### A constructor has a return type

No. `public Person() { }` is a constructor, while `public void Person() { }` is a method.

### An object initializer replaces the constructor

No. The object is constructed first, then its settable properties are assigned.

### Static means one copy for every object

No. Static means the member belongs to the type and is shared by that type.

### `this` means the class

Not exactly. `this` refers to the current object instance.

### `base` creates the parent object

No. `base` accesses base-class members or invokes the base constructor.

```text
Class             -> what an object looks like and can do
Object            -> actual instance
Field             -> stored data
Property          -> controlled access to data
Method            -> behavior
Constructor       -> initial object setup
Object initializer -> set properties during creation
Static            -> belongs to the type

```

The initialization order is:

```text
Base constructor
      -> Derived constructor
      -> Object initializer/property initialization
```
