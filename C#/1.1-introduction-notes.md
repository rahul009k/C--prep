# 🟦 C# 1.1 — Introduction

> **Revision status:** ✅ Complete — Strong / Recalled

Welcome to the foundation of the C# roadmap. This note connects the language, the .NET platform, the compiler, and the runtime into one clear mental model.

---

## 🧭 1. What Is C#?

**C# is a programming language developed by Microsoft.**

| Characteristic | Meaning |
| --- | --- |
| 🧱 Statically typed | Types are checked at compile time. |
| 🛠️ General-purpose | It can be used for many kinds of applications. |
| 🧩 Object-oriented | It supports classes, objects, inheritance, and polymorphism. |
| 🌐 .NET-focused | It is designed to work primarily with the .NET platform. |

```csharp
class Customer
{
    public string Name { get; set; }

    public void Print()
    {
        Console.WriteLine(Name);
    }
}
```

### 💡 Remember

> **C# = language**
>
> C# defines classes, interfaces, generics, delegates, properties, exceptions, `async`/`await`, pattern matching, and more.

---

## ⚖️ 2. C# vs .NET

These are related, but they are **not the same thing**.

| C# | .NET |
| --- | --- |
| The language you write | The platform and ecosystem that runs it |
| Provides syntax and language features | Provides the runtime, libraries, GC, threading, networking, and file APIs |

```text
C# = Language

.NET = Platform / Runtime + Libraries
```

Several languages can target .NET:

```text
C# ───┐
F# ───┼──> .NET
VB ───┘
```

---

## ⚙️ 3. CLR — Common Language Runtime

The **CLR** is the runtime environment in which managed .NET code executes.

It provides:

- 🗑️ Garbage collection
- 🧠 Memory management
- 🚨 Exception handling
- 🔎 Runtime type services
- ⚡ JIT compilation
- 🧵 Thread and runtime infrastructure

> **Important:** The CLR is not the C# compiler.

```text
C# compiler → produces IL + metadata
CLR/runtime → executes and manages the compiled application
```

---

## 🔨 4. Compilation

The CPU cannot directly understand C# syntax such as `int x = 10;`. Roslyn, the C# compiler, translates the source into **IL and metadata**.

```text
C# source
    ↓
C# compiler (Roslyn)
    ↓
IL + metadata
    ↓
Assembly (.dll / .exe)
```

### 🧩 IL, metadata, and managed code

| Term | Meaning |
| --- | --- |
| **IL** | Intermediate representation produced by the compiler |
| **Metadata** | Information describing types, members, references, and more |
| **Assembly** | The `.dll` or `.exe` package containing compiled code and metadata |
| **Managed code** | Code executing under the control and services of the .NET runtime |

```text
Managed code = IL ❌

C# source → IL → .NET runtime → managed execution ✅
```

---

## ⚡ 5. JIT — Just-In-Time Compiler

The JIT compiles IL into **native machine code** for the target machine.

```text
IL
 ↓
JIT
 ↓
Native machine code
 ↓
CPU
```

The JIT is one part of the .NET runtime, not the whole CLR:

```text
.NET Runtime / CLR
├── JIT
├── Garbage collector
├── Exception handling
├── Runtime type services
└── Other runtime services
```

---

## 🧠 6. Managed Code

> **Managed code is code that executes under the management and control of the .NET runtime.**

The runtime supplies services such as garbage collection, exception handling, runtime type management, and execution infrastructure.

⚠️ C# source code is not called “managed code” merely because it is written in C#. The key idea is **runtime-managed execution**.

---

## 🛤️ 7. Complete Compilation and Execution Pipeline

```text
             C# source code
                    │
                    ▼
          C# Compiler (Roslyn)
                    │
                    ▼
              IL + Metadata
                    │
                    ▼
              .NET Assembly
                    │
                    ▼
           .NET Runtime / CLR
                    │
                    ▼
                  JIT
                    │
                    ▼
          Native Machine Code
                    │
                    ▼
                   CPU
```

### 🎤 Interview-ready explanation

> C# source code is compiled by the C# compiler into IL and metadata stored in an assembly. When the application runs, the .NET runtime loads the assembly and provides runtime services. The JIT compiles the required IL into native machine code that the CPU can execute.

## 📦 9. Namespace

A namespace organizes and qualifies types. It is a **logical naming mechanism**, not a physical folder.

```csharp
namespace Sales
{
    class Customer { }
}

namespace Support
{
    class Customer { }
}
```

These are different types:

```text
Sales.Customer
Support.Customer
```

### Why use namespaces?

1. 🗂️ Organization
2. 🛡️ Avoiding type-name conflicts
3. 🎯 Providing fully qualified names

`namespace Company.Sales` does not require a matching `Company/Sales/` folder.

## 🔗 10. `using`

```csharp
System.Console.WriteLine("Hello");
```

| Part | Meaning |
| --- | --- |
| `System` | Namespace |
| `Console` | Class / type |
| `WriteLine` | Static method |

With this directive:

```csharp
using System;
```

you can write:

```csharp
Console.WriteLine("Hello");
```

> `using System` helps the compiler resolve types without repeating the namespace. It does not import all methods from `System`.

## 💬 11. Comments

### Single-line comment

```csharp
// Calculate total price
decimal total = price * quantity;
```

### Multi-line comment

```csharp
/*
    Calculate the total price
    including discount.
*/
decimal total = price * quantity;
```

### XML documentation comment

```csharp
/// <summary>
/// Calculates the total price.
/// </summary>
public decimal CalculateTotal(decimal price, int quantity)
{
    return price * quantity;
}
```

Normal comments are primarily for developers. XML documentation comments can be consumed by IDEs and documentation tools.

> **Practical rule:** Explain **why**, not obvious syntax.

```csharp
// Skip archived customers from the report.
```
