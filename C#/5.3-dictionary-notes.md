# 🟦 C# 5.3 — Dictionary<TKey, TValue>

> **Revision status:** ✅ Strong / Recalled

`Dictionary<TKey, TValue>` stores data as key-value pairs. It provides fast lookup by key and requires each key to be unique.

```csharp
Dictionary<int, string> employees = new();
```

Here:

```text
TKey   = int
TValue = string
```

The dictionary represents:

```text
Employee ID → Employee Name
```

---

## 🧠 1. What is a Dictionary?

A `List<T>` is useful when you access values by position:

```text
List<T>
index → value
```

A dictionary is useful when you access values by identity:

```text
Dictionary<TKey, TValue>
key → value
```

For example:

```csharp
Dictionary<int, string> employees = new();

employees.Add(101, "Rahul");
employees.Add(102, "Amit");
employees.Add(103, "Priya");
```

Conceptually:

```text
101 → Rahul
102 → Amit
103 → Priya
```

---

## 🎯 2. Why use a Dictionary?

A dictionary is appropriate when the important information is the key rather than the position.

Typical examples include:

```text
Employee ID → Employee
Product SKU → Product
Username → User
Country code → Country name
Configuration key → Configuration value
HTTP status code → Description
```

Dictionary lookup is generally **O(1) average** because it uses hashing to narrow the search to a likely bucket.

---

## 🔑 3. Keys and values

### Keys must be unique

```csharp
employees.Add(101, "Rahul");
employees.Add(101, "Amit");
```

The second call throws an `ArgumentException` because key `101` already exists.

### Values may repeat

```csharp
employees.Add(101, "Rahul");
employees.Add(102, "Rahul");
```

The keys are different, so this is valid even though both values are the same.

---

## ➕ 4. Adding items with `Add()`

```csharp
employees.Add(101, "Rahul");
employees.Add(102, "Amit");
```

`Add()` inserts a new key-value pair. If the key already exists, it throws:

```text
ArgumentException: An item with the same key has already been added.
```

---

## 📥 5. Retrieving with the indexer

```csharp
string name = employees[101];
Console.WriteLine(name); // Rahul
```

The indexer uses the key:

```text
List:    employees[0]
Dictionary: employees[101]
```

For a `List`, `0` is an index. For a dictionary, `101` is a key.

If the key does not exist, the indexer throws `KeyNotFoundException`.

---

## 🔍 6. `ContainsKey()`

Use `ContainsKey()` when you only need to determine whether a key exists.

```csharp
if (employees.ContainsKey(101))
{
    Console.WriteLine("Employee exists");
}
```

It returns a `bool`:

```csharp
employees.ContainsKey(101); // true
employees.ContainsKey(999); // false
```

`ContainsKey()` checks a key, not a value.

---

## 🧾 7. `TryGetValue()`

Use `TryGetValue()` when a key may not exist and you need the value when it does exist.

```csharp
if (employees.TryGetValue(101, out string name))
{
    Console.WriteLine(name);
}
```

The method returns:

```text
true  → key was found and value was assigned to the out variable
false → key was not found
```

```csharp
bool found = employees.TryGetValue(103, out string name);
```

If key `103` exists:

```text
found = true
name  = "Priya"
```

If key `103` does not exist:

```text
found = false
name  = null
```

### Why prefer it to `ContainsKey()`?

This code performs two lookups:

```csharp
if (employees.ContainsKey(101))
{
    string name = employees[101];
}
```

Using `TryGetValue()` performs one lookup and returns the value directly:

```csharp
if (employees.TryGetValue(101, out string name))
{
    // Use name.
}
```

---

## 🔀 8. `TryAdd()`

`TryAdd()` attempts to add a new key-value pair without throwing for an existing key.

```csharp
bool added = employees.TryAdd(101, "Rahul");
```

```text
true  → key did not exist and was added
false → key already existed
```

```csharp
employees.Add(101, "Rahul");

bool result = employees.TryAdd(101, "Sharma");

Console.WriteLine(result); // False
```

The existing value remains unchanged:

```text
101 → Rahul
```

---

## ⚖️ 9. `Add()`, indexer, and `TryAdd()`

```csharp
employees.Add(key, value);
```

- New key: adds the pair.
- Existing key: throws `ArgumentException`.

```csharp
employees[key] = value;
```

- New key: adds the pair.
- Existing key: replaces the value.

```csharp
employees.TryAdd(key, value);
```

- New key: adds the pair and returns `true`.
- Existing key: returns `false` and leaves the value unchanged.

### Memory aid

```text
Add()       duplicate → exception
[key] = value duplicate → replace
TryAdd()    duplicate → false
```

## 🧮 10. Dictionary and hashing

A dictionary uses a hash to find a likely location for a key.

Conceptual flow:

```text
Key
  ↓
GetHashCode()
  ↓
Hash code
  ↓
Bucket
  ↓
Candidate entry
  ↓
Equals()
  ↓
Value
```

### Hashing

Hashing transforms input into a hash result using a defined set of calculation rules.

Conceptually:

```text
Input
  ↓
Hashing algorithm
  ↓
Hash result
```

A dictionary normally uses the key type's existing `GetHashCode()` implementation. You do not normally implement a custom hashing algorithm.

---

## 🧾 11. Hash code and bucket

A hash code is an `int` returned by `GetHashCode()`.

```csharp
int hash = text.GetHashCode();
```

It is a 32-bit signed integer:

```text
-2,147,483,648 to 2,147,483,647
```

A hash code is not a fixed number of decimal digits. It may appear with different numbers of digits when converted to decimal.

A **bucket** is an internal location used by the dictionary to organize entries. The hash code helps determine the bucket; it is not itself the bucket.

```text
Hash code ≠ Bucket
```

---

## ⚠️ 12. Hash collisions

A hash collision occurs when different keys produce the same hash code or are placed in the same bucket.

```text
Key A → Hash 500 → Bucket 5
Key B → Hash 500 → Bucket 5
```

This does not mean `Key A == Key B`.

The dictionary must compare the actual keys after narrowing the search.

```text
Hash code
  ↓
Find candidate area
  ↓
Equals()
  ↓
Confirm the exact key
```

### Equality and hash contract

For correctly implemented equality:

```text
Equal objects → Same hash code
```

The reverse is not guaranteed:

```text
Same hash code → Could be different objects
```

```csharp
A.Equals(B) == true
```

must imply:

```csharp
A.GetHashCode() == B.GetHashCode()
```

However, equal hash codes do not prove equality.

---

## 🧩 13. `Equals()` and `GetHashCode()`

For a custom type, equality can be defined by a property such as an ID:

```csharp
class Employee
{
    public int Id { get; set; }

    public override bool Equals(object? obj)
    {
        return obj is Employee other && Id == other.Id;
    }

    public override int GetHashCode()
    {
        return Id.GetHashCode();
    }
}
```

```csharp
Employee e1 = new() { Id = 101 };
Employee e2 = new() { Id = 101 };

Console.WriteLine(e1.Equals(e2)); // True
Console.WriteLine(e1.GetHashCode() == e2.GetHashCode()); // True
```

The two methods solve different problems:

```text
GetHashCode() → Helps locate the candidate bucket
Equals()      → Confirms whether the keys are actually equal
```

---

## 🔒 14. Mutable Dictionary keys

Do not change fields used by `Equals()` or `GetHashCode()` while the object is used as a dictionary key.

```csharp
Employee employee = new() { Id = 101 };

dictionary[employee] = "Rahul";
employee.Id = 999;
```

The dictionary stored the entry using the object's previous hash-related state. Changing `Id` can make future lookups search in a different bucket and fail to find the entry.

Immutable objects are safer dictionary keys.

---

## ⚡ 15. Dictionary versus List performance

### List search

A `List<T>` usually searches sequentially:

```text
Element 1
  ↓
Element 2
  ↓
Element 3
  ↓
...
```

Worst case: `O(n)`.

### Dictionary lookup

```text
Key
  ↓
Hash
  ↓
Bucket
  ↓
Candidate
  ↓
Equality check
  ↓
Value
```

Average case: `O(1)`.

Worst case: `O(n)` when too many keys collide in the same bucket.

The `O(1)` result is an average-case advantage, not a guarantee.

## 🔁 16. Iterating through a Dictionary

```csharp
foreach (var item in employees)
{
    Console.WriteLine(item.Key);
    Console.WriteLine(item.Value);
}
```

Each `item` is a `KeyValuePair<TKey, TValue>`.

```csharp
foreach (var item in employees)
{
    Console.WriteLine($"{item.Key} {item.Value}");
}
```

Output:

```text
101 Rahul
102 Amit
103 Priya
```

## 🧠 Final mental model

```text
Dictionary
    │
    ▼
Key
    │
    ▼
GetHashCode()
    │
    ▼
Hash code
    │
    ▼
Bucket
    │
    ▼
Candidate entry
    │
    ▼
Equals()
    │
    ├── Equal → Return value
    └── Not equal → Check another candidate
```

### Most important rules

```text
Dictionary = key → value
Keys must be unique.
Hashing helps locate entries.
Hash code ≠ bucket.
Same hash ≠ same key.
Equals() confirms equality.
Equal objects must have the same hash code.
Dictionary lookup = O(1) average.
List search = O(n).
Add() with duplicate key = exception.
TryAdd() with duplicate key = false.
[key] = value replaces an existing value.
TryGetValue() safely checks and retrieves.
Do not mutate hash/equality-related state of a dictionary key.
```
