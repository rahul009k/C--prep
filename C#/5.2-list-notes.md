# 🟦 C# 5.2 — List<T>

> **Revision status:** ✅ Strong / Recalled

`List<T>` is a generic, dynamically sized collection used to store multiple values of the same type.

```csharp
List<int> numbers = new List<int>();

numbers.Add(10);
numbers.Add(20);
numbers.Add(30);
```

---

## 🧠 1. Why does `List<T>` exist?

An array has a fixed length after it is created.

```csharp
int[] numbers = new int[3];
```

The array can hold exactly `3` elements.

If you need more storage, you have to create another array and copy or resize the data.

`List<T>` solves this problem by managing its internal storage automatically.

```csharp
List<int> numbers = new List<int>();

numbers.Add(10);
numbers.Add(20);
numbers.Add(30);
numbers.Add(40);
numbers.Add(50);
```

The list automatically manages its internal storage as elements are added.

### Important

`List<T>` is dynamically sized from the programmer's perspective, but internally it uses array-like storage.

---

## 🧩 2. Generics — `List<T>`

`T` represents the type of element stored in the list.

```csharp
List<int> numbers;
List<string> names;
List<Employee> employees;
```

Conceptually:

```text
List<int>
    ↓
T = int

List<string>
    ↓
T = string

List<Employee>
    ↓
T = Employee
```

Because the type is known, C# provides compile-time type safety.

```csharp
List<int> numbers = new List<int>();

numbers.Add(10);       // valid
numbers.Add(20);       // valid
numbers.Add("Hello"); // ❌ compile-time error
```

---

## 📏 3. Count

`Count` tells you how many actual elements are currently in the list.

```csharp
List<int> numbers = new List<int>();

numbers.Add(10);
numbers.Add(20);
numbers.Add(30);

Console.WriteLine(numbers.Count);
```

Output:

```text
3
```

`Count` is a property, not a method.

```csharp
numbers.Count;     // ✅
numbers.Count();   // ❌
```

---

## 🗂️ 4. Capacity

`Capacity` represents the amount of internal storage currently available for elements before the list needs to grow.

Example:

```text
Count    = 5
Capacity = 8
```

This means:

```text
5 actual elements
8 element storage available
```

Therefore:

```text
Count <= Capacity
```

always.

---

## ⚖️ 5. Count vs Capacity

This is one of the most important `List<T>` concepts.

```text
Count
  ↓
How many elements actually exist?

Capacity
  ↓
How much internal storage is currently available?
```

Example:

```csharp
List<int> numbers = new List<int>(10);
```

This means:

```text
Count    = 0
Capacity = 10
```

It does not mean that 10 elements already exist.

After:

```csharp
numbers.Add(100);
numbers.Add(200);
```

we have:

```text
Count    = 2
Capacity = 10
```

---

## 📈 6. What happens when Capacity becomes full?

Suppose:

```text
Count    = 4
Capacity = 4
```

The internal storage is full.

When:

```csharp
numbers.Add(50);
```

is executed, the list needs more storage.

Conceptually:

```text
Old storage:

[10][20][30][40]

        ↓

New larger storage:

[10][20][30][40][50][ ][ ][ ]
```

The list implementation obtains larger internal storage and copies the existing elements.

Therefore, most `Add()` operations are efficient, but an occasional `Add()` can be more expensive because of this growth and copy operation.

### Important

Do not depend on an exact growth strategy such as:

```text
"Capacity always doubles."
```

The exact growth strategy is an implementation detail.

## ➕ 7. `Add()`

Adds one element to the end of the list.

```csharp
List<int> numbers = new List<int>();

numbers.Add(10);
numbers.Add(20);
numbers.Add(30);
```

Result:

```text
10, 20, 30
```

Conceptually:

```text
Add()
 ↓
Add one T
```

---

## ➕ 8. `AddRange()`

Adds multiple elements.

```csharp
List<int> numbers = new List<int>();

numbers.AddRange(new int[] { 10, 20, 30 });
```

Result:

```text
10, 20, 30
```

### Difference

```text
Add()
    → one element

AddRange()
    → multiple elements
```

---

## 🧠 9. `Add()` vs `AddRange()` and Generics

Consider:

```csharp
List<int> numbers = new List<int>();
```

Here `T` is `int`.

Therefore:

```csharp
numbers.Add(10);
```

adds one `int`.

And:

```csharp
numbers.AddRange(new[] { 20, 30, 40 });
```

adds multiple `int` values.

But:

```csharp
numbers.Add(new[] { 40, 50 });
```

doesn't compile because:

```text
List<int>
expects → int

new[] { 40, 50 }
is      → int[]
```

If we instead have:

```csharp
List<int[]> numbers = new List<int[]>();
```

then:

```csharp
numbers.Add(new[] { 40, 50 });
```

adds one `int[]` as one element.

## ❌ 10. `Remove()`

Removes the first matching element.

```csharp
List<int> numbers = new List<int>
{
    10, 20, 30, 20, 40
};

numbers.Remove(20);
```

Result:

```text
10, 30, 20, 40
```

Only the first `20` is removed.

---

## 🗑️ 11. `RemoveAt()`

Removes an element using its index.

```csharp
List<int> numbers = new List<int>
{
    10, 20, 30, 40
};

numbers.RemoveAt(1);
```

Before:

```text
Index:   0   1   2   3
Value:  10  20  30  40
```

After:

```text
Index:   0   1   2
Value:  10  30  40
```

The elements after the removed element shift left.

---

## 🧹 12. `RemoveAll()`

Removes all elements satisfying a condition.

```csharp
List<int> numbers = new List<int>
{
    10, 20, 30, 20, 40
};

numbers.RemoveAll(x => x == 20);
```

Result:

```text
10, 30, 40
```

The lambda:

```csharp
x => x == 20
```

means:

> Remove `x` when `x` is equal to 20.

---

## 🔍 13. `Remove()` vs `RemoveAt()` vs `RemoveAll()`

```text
Method              Meaning
Remove(value)       Remove first matching value
RemoveAt(index)     Remove element at index
RemoveAll(condition) Remove every matching element
```

Think:

```text
Remove
    → "Remove this value."

RemoveAt
    → "Remove this position."

RemoveAll
    → "Remove everything matching this rule."
```

---

## 🏷️ 14. `Insert()`

`Insert()` adds an element at a specific index.

```csharp
List<int> numbers = new List<int>
{
    10, 20, 30, 40
};

numbers.Insert(2, 99);
```

Before:

```text
Index:   0   1   2   3
Value:  10  20  30  40
```

After:

```text
Index:   0   1   2   3   4
Value:  10  20  99  30  40
```

### Important

`Insert()` does not replace the existing element.

It increases `Count` and shifts existing elements to the right.

```text
Before:
10 20 30 40

Insert(2, 99)

After:
10 20 99 30 40
```

---

## ⏱️ 15. Why is middle insertion more expensive?

`List<T>` uses array-like contiguous internal storage.

Suppose:

```text
[10][20][30][40]
```

Insert `99` at index `1`:

```text
[10][99][20][30][40]
```

Existing elements have to move.

Conceptually:

```text
20 → right
30 → right
40 → right
```

Therefore:

> Adding at the end is generally cheaper than inserting in the middle because middle insertion may require shifting existing elements.

---

## ✅ 16. `Contains()`

`Contains()` checks whether an element exists.

```csharp
List<int> numbers = new List<int>
{
    10, 20, 30
};

bool result = numbers.Contains(20);
```

Result:

```text
true
```

If:

```csharp
numbers.Contains(50);
```

the result is:

```text
false
```

### Important

`Contains()` returns a `bool`.

It answers:

> "Does a matching element exist?"

It does not tell you the index.

---

## 🎯 17. `Find()`

`Find()` returns the first element that satisfies a condition.

```csharp
List<int> numbers = new List<int>
{
    5, 12, 18, 25, 30
};

int result = numbers.Find(x => x > 15);
```

Result:

```text
18
```

Why?

The list is checked from the beginning:

```text
5  → false
12 → false
18 → true  ← first match
```

Once the first matching element is found, it is returned.

---

## 🔄 18. `Find()` vs `Contains()`

```text
Contains()
    ↓
bool
    ↓
"Does a match exist?"

Find()
    ↓
T
    ↓
"Give me the first matching element."
```

Example:

```csharp
numbers.Contains(20);
```

returns:

```text
true
```

Whereas:

```csharp
numbers.Find(x => x > 15);
```

returns:

```text
18
```

---

## 🧮 19. `FindAll()`

`FindAll()` returns all elements satisfying a condition.

```csharp
List<int> numbers = new List<int>
{
    5, 12, 18, 25, 30
};

List<int> result = numbers.FindAll(x => x > 15);
```

Result:

```text
18, 25, 30
```

Difference:

```text
Find()
    → first matching element
    → T

FindAll()
    → all matching elements
    → List<T>
```

---

## ⚠️ 20. What if `Find()` finds nothing?

For value types, `Find()` returns the default value of `T`.

For example:

```csharp
int result = numbers.Find(x => x > 100);
```

If nothing matches:

```text
default(int) = 0
```

For reference types, the result can be `null`.

Therefore, real-world code should consider the possibility that nothing matched.

---

## 🔠 21. `Sort()`

`Sort()` rearranges the existing list according to its sorting rules.

```csharp
List<int> numbers = new List<int>
{
    40, 10, 30, 20
};

numbers.Sort();
```

Result:

```text
10, 20, 30, 40
```

### Important

`Sort()` modifies the existing list.

It does not create a separate sorted list.

---

## ⬇️ 22. Descending order

Default numeric sorting is ascending.

```csharp
numbers.Sort();
numbers.Reverse();
```

Result:

```text
40, 30, 20, 10
```

`Reverse()` reverses the current order.

It is not itself a descending sort algorithm.

---

## 🧑‍💼 23. Sorting custom objects

For custom classes, the list needs a comparison rule.

Example:

```csharp
class Employee
{
    public int Id { get; set; }
    public string Name { get; set; }
}
```

We can sort employees by `Id`:

```csharp
employees.Sort((a, b) => a.Id.CompareTo(b.Id));
```

The important theory is:

> Sorting requires a way to determine which element should come before another.

## 🧠 24. Important `List<T>` mental model

Think of a `List<T>` like this:

```text
List<T>

        Count
          ↓
┌────┬────┬────┬────┬────┬────┐
│ T  │ T  │ T  │    │    │    │
└────┴────┴────┴────┴────┴────┘
          ↑
       Capacity
```

For example:

```text
Count = 3
Capacity = 6
```

There are 3 actual elements but storage for 6.

```text

Storage fixed after creation
```

```text

    → fixed-size storage

```

## ❌ 26. Important misconceptions

### Misconception 1

> "Capacity means number of elements."

❌ Wrong.

```text
Count = actual elements
Capacity = available internal storage
```

### Misconception 2

> "`new List<int>(10)` creates 10 elements."

❌ Wrong.

It creates a list with initial capacity for approximately 10 elements.

```text
Count = 0
Capacity = 10
```

### Misconception 3

> "Remove() removes every matching value."

❌ Wrong.

```csharp
Remove(20)
```

removes the first matching value.

Use:

```csharp
RemoveAll(x => x == 20)
```

to remove all matching values.

### Misconception 4

> "`Insert()` replaces the element at that index."

❌ Wrong.

It inserts a new element and shifts existing elements.

### Misconception 5

> "`Contains()` gives the index."

❌ Wrong.

`Contains()` returns only:

```text
true / false
```

Use an index-search operation when you need the position.

### Misconception 6

> "`Sort()` creates a new sorted list."

❌ Wrong.

`Sort()` modifies the existing list.

### Misconception 7

> "The compiler increases list capacity."

❌ Wrong.

The `List<T>` implementation manages its internal storage at runtime.

## ⚙️ 27. Performance intuition

You do not need to memorize every Big-O detail yet, but understand the reason behind the costs.

### Access by index

```csharp
numbers[5]
```

Generally efficient because the list uses array-like indexed storage.

### Add at end

```csharp
numbers.Add(100);
```

Usually efficient.

Occasionally more expensive when capacity needs to grow.

### Insert/remove in middle

```csharp
numbers.Insert(2, 100);
numbers.RemoveAt(2);
```

Can require shifting elements.

Therefore, potentially more expensive.

### Search

```csharp
numbers.Contains(100);
numbers.Find(x => x == 100);
```

May need to examine elements from the beginning until a match is found.

## ❓ Understanding questions

1. What is the difference between `Count` and `Capacity`?
   - `Count` is the number of actual elements currently stored in the list.
   - `Capacity` is the amount of internal storage currently available before the list must grow.

2. Why doesn't `List<T>` increase its internal storage on every `Add()`?
   - Growing the internal array on every insertion would be inefficient and would cause too much copying.
   - The list grows only when the current capacity is full, so it amortizes the cost over many additions.

3. What happens internally when you `Add()` an element and the capacity is already full?
   - The list allocates a larger internal array.
   - It copies all existing elements into the new array.
   - Then it inserts the new element at the end.

4. What is the difference between `Add()` and `AddRange()`?
   - `Add()` inserts one element.
   - `AddRange()` inserts multiple elements at once, often from an array or another collection.

5. What is the difference between `Remove()`, `RemoveAt()`, and `RemoveAll()`?
   - `Remove(value)` removes the first matching value.
   - `RemoveAt(index)` removes the element at a specific index.
   - `RemoveAll(condition)` removes every element matching a predicate.

6. Why does inserting an element in the middle of a `List<T>` require shifting?
   - The list stores elements contiguously in memory.
   - To insert at index `i`, all elements after that point must move one slot to the right.

7. What is the difference between `Contains()` and `Find()`?
   - `Contains()` returns a `bool` indicating whether a value exists.
   - `Find()` returns the first matching element itself.

8. What does `FindAll()` return compared with `Find()`?
   - `Find()` returns the first match only.
   - `FindAll()` returns a new `List<T>` containing all matching elements.

9. Does `Insert()` replace an existing element?
   - No. `Insert()` adds a new element at that index and shifts the existing items to the right.

10. Does `Sort()` create a new List or modify the existing List?
    - It modifies the existing list in place.

11. Why does `List<T>` use generics?
    - Generics give compile-time type safety.
    - A `List<int>` cannot accidentally store a `string`, which prevents type errors and improves performance.

12. What does `new List<int>(10)` actually mean?
    - It creates a `List<int>` with an initial internal capacity of about `10`.
    - `Count` is still `0` until elements are added.

## 🧪 Interview questions

### Basic

1. What is `List<T>` and why would you use it instead of an array?
   - `List<T>` is a dynamically sized generic collection that can grow as needed.
   - It is preferred when the number of items is not fixed in advance.

2. What is the difference between `Count` and `Capacity`?
   - `Count` is the number of actual elements.
   - `Capacity` is the available internal storage.

3. Is `List<T>` dynamically sized internally?
   - Yes, from the programmer's perspective it grows automatically as needed.

4. What happens when a list reaches its capacity?
   - It allocates a larger internal array and copies the old elements into it.

5. What is the difference between `Remove()` and `RemoveAt()`?
   - `Remove(value)` removes the first matching value.
   - `RemoveAt(index)` removes by position.

6. What does `RemoveAll()` do?
   - It removes all elements that match a condition or predicate.

7. What is the difference between `Find()` and `FindAll()`?
   - `Find()` returns the first matching element.
   - `FindAll()` returns all matching elements as a new `List<T>`.

8. What does `Contains()` return?
   - It returns a `bool` indicating whether the value exists.

9. What does `Insert()` do?
   - It inserts a new element at a specific index and shifts the rest right.

10. Does `Sort()` modify the original List?
    - Yes, it sorts the list in place.

### Intermediate

1. Why can `Add()` occasionally be more expensive than normal?
   - Because the list may need to allocate a larger internal array and copy existing elements.

2. Why is adding to the end generally cheaper than inserting into the middle?
   - Appending at the end avoids shifting existing elements.

3. Why can removing from the middle require shifting elements?
   - Because the list stores elements contiguously, so removing an index leaves a gap that must be filled.

4. Why is `List<T>` backed by array-like storage?
   - It allows fast indexed access and efficient memory layout.

5. Why are generics preferable to storing everything as `object`?
   - They preserve type safety, avoid boxing, and reduce runtime errors.

6. What happens if `Find()` doesn't find a matching element?
   - For value types, it returns the default value of `T`.
   - For reference types, it may return `null`.

7. What is the difference between `List<int>` and `List<int[]>`?
   - `List<int>` stores individual integers.
   - `List<int[]>` stores arrays of integers as each element.

8. When would you choose an array instead of `List<T>`?
   - When the size is fixed and known in advance, and performance or memory constraints favor a fixed-size container.

### Interview reasoning question

> If you know beforehand that you're going to add approximately 10,000 elements to a `List<T>`, why might you create it as `new List<int>(10000)` instead of simply using `new List<int>()`?

Because `new List<int>(10000)` pre-allocates internal storage for around 10,000 elements. This reduces the number of times the list has to resize and copy its data as you add items. It can improve performance when the final size is known or approximately known, especially for large collections.
