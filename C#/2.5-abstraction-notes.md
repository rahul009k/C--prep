# C# 2.5 - Abstraction

> **Revision status:** Strong / Recalled

Abstraction exposes the essential behavior an object offers while hiding implementation details that callers do not need.

```text
WHAT an object can do -> expose
HOW it does it       -> hide
```

For example, calling `car.Start()` communicates the operation without requiring the caller to understand the fuel, sensors, timing, battery, and ignition details behind it.

Abstraction helps reduce complexity, focus code on relevant behavior, and limit dependencies on implementation details.

---

## 1. Abstraction and Encapsulation

These ideas are related, but answer different questions:

| Concept | Main question | Purpose |
| --- | --- | --- |
| Encapsulation | Who can access or change this? | Control access to data and implementation |
| Abstraction | What behavior should be exposed? | Present a useful, simplified contract |

```csharp
class BankAccount
{
    private decimal _balance;

    public void Deposit(decimal amount)
    {
        if (amount > 0)
        {
            _balance += amount;
        }
    }
}
```

The private balance and the `Deposit` operation demonstrate encapsulation. A caller can use the account's public behavior without directly changing its internal balance.

## 2. Abstract Classes

An abstract class cannot be instantiated directly. It can combine shared implementation with members that derived classes must implement.

```csharp
abstract class Animal
{
    public string Name { get; set; }

    public void Eat()
    {
        Console.WriteLine("Animal is eating");
    }

    public abstract void MakeSound();
}
```

`Animal` provides a shared `Eat` method and requires a concrete derived class to provide `MakeSound`.

```csharp
// Invalid: Animal is abstract.
// Animal animal = new Animal();

Animal animal = new Dog();
```

An abstract class is useful when related types share state or behavior, but some behavior must vary by derived type.

```csharp
abstract class Employee
{
    public void Login()
    {
        Console.WriteLine("Employee logged in");
    }

    public abstract void Work();
}

class Developer : Employee
{
    public override void Work()
    {
        Console.WriteLine("Writing code");
    }
}

class Tester : Employee
{
    public override void Work()
    {
        Console.WriteLine("Testing application");
    }
}
```

`Login` is common behavior; `Work` is type-specific behavior.

An abstract class may contain fields, properties, constructors, concrete methods, abstract methods, static members, and other class members. `abstract` means the class cannot be instantiated directly; it does not mean every member must be abstract.

### Abstract class constructors

An abstract class can declare a constructor. It runs as part of constructing a derived-class instance.

```csharp
abstract class Employee
{
    protected Employee(string name)
    {
        Name = name;
    }

    public string Name { get; }

    public abstract void Work();
}

class Developer : Employee
{
    public Developer(string name) : base(name)
    {
    }

    public override void Work()
    {
        Console.WriteLine("Writing code");
    }
}

Employee employee = new Developer("Rahul");
```

The base constructor initializes the shared `Name` state while the derived object is created.

## 3. Abstract Methods

An abstract method has no body and requires a non-abstract derived class to provide an override.

```csharp
abstract class Animal
{
    public abstract void MakeSound();
}

class Dog : Animal
{
    public override void MakeSound()
    {
        Console.WriteLine("Woof");
    }
}
```

A derived class that does not implement all inherited abstract members must itself be declared `abstract`.

```csharp
abstract class SpecializedAnimal : Animal
{
    // Allowed: this class remains abstract.
}
```

## 4. Virtual and Abstract Members

| Member | Base implementation | Must a concrete derived class implement it? | Can a derived class override it? |
| --- | --- | --- | --- |
| `virtual` | Yes | No | Yes, optionally |
| `abstract` | No | Yes | Yes, required |

```csharp
class Animal
{
    public virtual void MakeSound()
    {
        Console.WriteLine("Some sound");
    }
}
```

A derived class may override this default:

```csharp
class Dog : Animal
{
    public override void MakeSound()
    {
        Console.WriteLine("Woof");
    }
}
```

```text
virtual  -> base implementation exists; overriding is optional
abstract -> no base implementation; a concrete derived type must implement it
```

## 5. Interfaces

An interface defines a contract: the operations or other members a type makes available. A class implements the contract and supplies the behavior.

```csharp
interface IPayment
{
    void ProcessPayment();
}

class UpiPayment : IPayment
{
    public void ProcessPayment()
    {
        Console.WriteLine("Processing UPI payment");
    }
}
```

Interfaces let code depend on a contract instead of a concrete implementation.

```csharp
static void Checkout(IPayment payment)
{
    payment.ProcessPayment();
}

Checkout(new UpiPayment());
Checkout(new CardPayment());
```

`Checkout` only needs the `IPayment` contract; it does not need to know how each payment type works.

### Interface references

A class instance can be referenced through an interface it implements:

```csharp
interface IPrintable
{
    void Print();
}

class Invoice : IPrintable
{
    public void Print()
    {
        Console.WriteLine("Printing invoice");
    }
}

IPrintable document = new Invoice();
```

There is one `Invoice` object. The interface-typed reference exposes only the members available through `IPrintable`.

```csharp
static void PrintDocument(IPrintable document)
{
    document.Print();
}
```

Any type implementing `IPrintable` can be passed to `PrintDocument`.

```text
Reference type -> controls which members can be accessed
Actual object  -> supplies the runtime implementation
```

### Interface members

Interfaces can define method, property, event, and indexer contracts. They do not have instance fields or instance constructors.

```csharp
interface IPayment
{
    decimal Amount { get; }

    void ProcessPayment();
}

class UpiPayment : IPayment
{
    public decimal Amount { get; }

    public UpiPayment(decimal amount)
    {
        Amount = amount;
    }

    public void ProcessPayment()
    {
        Console.WriteLine("Processing UPI");
    }
}
```

### Implementing multiple interfaces

A class can implement multiple interfaces, each representing a separate contract or capability.

```csharp
interface IPrintable
{
    void Print();
}

interface IExportable
{
    void Export();
}

class Invoice : IPrintable, IExportable
{
    public void Print()
    {
        Console.WriteLine("Printing invoice");
    }

    public void Export()
    {
        Console.WriteLine("Exporting invoice");
    }
}
```

A class can derive from at most one class, but it can implement multiple interfaces:

```csharp
class Invoice : Document, IPrintable, IExportable
{
    // Implement the required members.
}
```

Say that `Invoice` **implements** `IPrintable`; interfaces are contracts, not base classes.

### Different interface views

```csharp
interface ILogger
{
    void Log();
}

interface ICacheable
{
    void Cache();
}

class UserService : ILogger, ICacheable
{
    public void Log() => Console.WriteLine("Logging");
    public void Cache() => Console.WriteLine("Caching");
}

ILogger service = new UserService();
service.Log();
// service.Cache(); // Not available through ILogger.
```

The same object can be viewed through either interface, but each reference exposes its own contract.

## 6. Default Interface Methods

A default interface method has a body in the interface. This feature was introduced in C# 8.0, primarily to allow interfaces to evolve without immediately requiring every existing implementer to add a new member.

```csharp
interface ILogger
{
    void Log(string message);

    void LogError(string message)
    {
        Console.WriteLine($"ERROR: {message}");
    }
}

class FileLogger : ILogger
{
    public void Log(string message)
    {
        Console.WriteLine(message);
    }
}

ILogger logger = new FileLogger();
logger.Log("Hello");
logger.LogError("Something went wrong");
```

`FileLogger` can use the interface-provided implementation without declaring its own `LogError`. The call is made through the interface contract; the concrete class does not automatically expose that default member as a class member.

## 7. Abstract Class vs Interface

| Feature | Abstract class | Interface |
| --- | --- | --- |
| Can be instantiated directly? | No | No |
| Can provide implementation? | Yes | Yes, with default interface members |
| Can require members from implementers/derived types? | Yes, with abstract members | Yes, with required contract members |
| Can have instance fields? | Yes | No |
| Can have instance properties? | Yes | Yes |
| Can have an instance constructor? | Yes | No |
| Can a type use multiple? | One base class | Multiple interfaces |
| Typical role | Shared base and implementation for related types | Contract or capability across types |

```text
Abstract class -> What do these related types share? (IS-A)
Interface      -> What contract or capability does this type provide? (CAN-DO)
```

For example, `Bird` can derive from `Animal` and implement `IFlyable`: it **is an** animal and **can** fly.

## 8. Abstraction and Polymorphism

Abstraction defines the common contract. Polymorphism lets different implementations be used through that contract.

```csharp
abstract class Payment
{
    public abstract void ProcessPayment();
}

class UpiPayment : Payment
{
    public override void ProcessPayment()
    {
        Console.WriteLine("Processing UPI");
    }
}

class CardPayment : Payment
{
    public override void ProcessPayment()
    {
        Console.WriteLine("Processing card");
    }
}

Payment payment = new UpiPayment();
payment.ProcessPayment();
```

The `Payment` abstraction exposes `ProcessPayment`; runtime polymorphism dispatches the call to `UpiPayment`'s implementation.

### Example: payment gateway

```csharp
interface IPaymentGateway
{
    void ProcessPayment(decimal amount);
}

class RazorpayGateway : IPaymentGateway
{
    public void ProcessPayment(decimal amount)
    {
        Console.WriteLine($"Processing {amount} using Razorpay");
    }
}

class StripeGateway : IPaymentGateway
{
    public void ProcessPayment(decimal amount)
    {
        Console.WriteLine($"Processing {amount} using Stripe");
    }
}

class OrderService
{
    private readonly IPaymentGateway _paymentGateway;

    public OrderService(IPaymentGateway paymentGateway)
    {
        _paymentGateway = paymentGateway;
    }

    public void PlaceOrder(decimal amount)
    {
        _paymentGateway.ProcessPayment(amount);
    }
}

var service = new OrderService(new RazorpayGateway());
service.PlaceOrder(1000);
```

`OrderService` depends on `IPaymentGateway`, so a different implementation can be supplied without changing the order-service logic.

## 9. Common Misconceptions

- **An abstract class cannot contain normal methods.** It can contain both concrete and abstract members.
- **An abstract class cannot have a constructor.** It can; the constructor runs while a derived instance is created.
- **An interface can contain only methods.** Interfaces can also define properties, events, and indexers.
- **A class can inherit multiple classes.** C# allows one base class, plus multiple implemented interfaces.
- **`virtual` and `abstract` mean the same thing.** A virtual member has a default implementation and may be overridden; an abstract member has no implementation and must be implemented by a concrete derived class.
- **An interface reference creates a separate object.** It refers to the same object through a narrower contract.

## 10. Quick Memory Sheet

| Term | Remember |
| --- | --- |
| Abstraction | Expose essential behavior; hide implementation details. |
| Abstract class | Non-instantiable class that can combine shared implementation and abstract members. |
| Abstract method | Bodyless member that a concrete derived class must implement. |
| Interface | Contract describing members a type provides. |
| Multiple interfaces | One class can provide several independent contracts or capabilities. |
| Default interface method | Interface member with a body that can support interface evolution. |
| Virtual method | Base implementation exists; derived classes may override it. |
| Reference type | Determines which members are accessible through that reference. |
| Actual object | Determines which overridden implementation runs. |

```text
Abstraction -> WHAT is exposed; HOW is hidden
Abstract    -> base has no implementation; concrete derived type must implement
Virtual     -> base implementation exists; derived type may override
Interface   -> contract or capability
```

### Interview one-liners

**What is abstraction?**

> Abstraction exposes essential behavior while hiding implementation details.

**Why can't an abstract class be instantiated?**

> It represents an incomplete base abstraction and may declare members without implementations.

**Can an abstract class contain concrete methods or a constructor?**

> Yes. Concrete methods provide shared behavior, and its constructor runs as part of constructing a derived object.

**What is the difference between abstract and virtual?**

> An abstract member has no implementation and must be implemented by a concrete derived class; a virtual member has a default implementation and may be overridden.

**What is an interface, and why use one?**

> An interface defines a contract. Depending on that contract instead of a concrete class allows implementations to be substituted and types to provide multiple capabilities.

**Can a class implement multiple interfaces?**

> Yes. A class can have one base class and implement multiple interfaces.

**What are default interface methods?**

> They are interface members with a body, introduced in C# 8.0 to help evolve interfaces without immediately requiring every implementer to add an implementation.
