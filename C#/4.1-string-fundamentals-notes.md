# C# 4.1 - String Fundamentals

> **Revision status:** Strong / Recalled

A `string` represents a sequence of characters. `string` is a C# alias for `System.String`.

```csharp
string name = "Rahul";
```

---

## 1. Strings Are Reference Types

A string variable holds a reference to a string object. Assigning one string variable to another copies the reference:

```csharp
string first = "Rahul";
string second = first;
```

Conceptually, both variables refer to the same string object. However, strings are immutable, so string operations do not change that object's contents.

---

## 2. Strings Are Immutable

Immutable means that once a string object is created, its contents cannot be changed. Reassigning a variable makes it refer to a different string; it does not modify the original string.

```csharp
string name = "Rahul";
name = "Amit";
```

After reassignment, `name` refers to `"Amit"`. The original `"Rahul"` string was not changed.

---

## 3. Concatenation

The `+` operator joins strings. Because strings are immutable, concatenation produces a string with the combined contents rather than modifying either input string.

```csharp
string firstName = "Rahul";
string lastName = "Kumar";

string fullName = firstName + " " + lastName;
Console.WriteLine(fullName); // Rahul Kumar
```

---

## 4. Common String Members

```csharp
string name = "Rahul";

int length = name.Length;
string upper = name.ToUpper();
string lower = name.ToLower();
bool contains = name.Contains("ah");
bool startsWith = name.StartsWith("Ra");
bool endsWith = name.EndsWith("ul");
string beginning = name.Substring(0, 3);
string replacement = name.Replace("Rahul", "Amit");
```

`Length` is a property. Methods such as `ToUpper`, `ToLower`, and `Replace` return strings; they do not change the original string.

```csharp
string name = "rahul";
string upper = name.ToUpper();

Console.WriteLine(name);  // rahul
Console.WriteLine(upper); // RAHUL
```

---

## 5. String Equality

The `==` operator compares string contents, not just whether the variables refer to the same object.

```csharp
string first = "Rahul";
string second = "Rahul";

Console.WriteLine(first == second); // True
```

This differs from the default `==` behavior of an ordinary class, which compares object references unless the class overloads the operator.

---

## 6. Empty and Null Strings

`string.Empty` and `""` both represent an empty string: a string with zero characters.

```csharp
string empty = string.Empty;
string alsoEmpty = "";
```

`null` is different: it means there is no string reference. In projects with nullable reference types enabled, use `string?` to indicate that a string may be null.

```csharp
string? missing = null;
string empty = "";
```

```text
null  -> no string reference
""    -> a string containing zero characters
```

---

## 7. String Interpolation

Interpolated strings use `$` and put expressions inside braces. This is often easier to read than concatenating several values.

```csharp
string name = "Rahul";
int age = 25;

string message = $"Hello {name}, your age is {age}";
```

---

## 8. Verbatim Strings and Escape Sequences

A verbatim string literal uses `@`; backslashes are treated as ordinary characters. It is convenient for Windows paths.

```csharp
string path = @"C:\Users\Rahul\Documents";
```

Without `@`, backslashes that are part of the text must be escaped:

```csharp
string path = "C:\\Users\\Rahul\\Documents";
```

Common escape sequences include:

```text
\n  -> new line
\t  -> tab
\"  -> double quote
\\  -> backslash
```

```csharp
string message = "Hello\nRahul";
```

This displays `Rahul` on the line after `Hello`.

---

## 9. Quick Memory Sheet

```text
string                  -> reference type
string                  -> immutable
string second = first;  -> copies the reference
first = "New Value";    -> makes first refer to a different string
==                      -> compares string contents
string.Empty            -> empty string
null                    -> no string reference
$"Hello {name}"        -> string interpolation
@"C:\\folder"         -> verbatim string literal
```

> **Key idea:** A string is a reference type, but it is immutable. Reference type does not mean mutable object.
