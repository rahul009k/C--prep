# C# 3.1 - Structs

> **Revision status:** Strong / Recalled

A `struct` is a value type. Use one to represent a value with value-like semantics, rather than an entity whose identity and shared mutable state are central.

```csharp
struct Point
{
    public int X;
    public int Y;
}
```

Common value types include `int`, `decimal`, `DateTime`, and `Guid`. Structs can also contain reference-type fields.

---

## 1. Struct vs Class

| Struct | Class |
| --- | --- |
| Value type | Reference type |
| Assignment copies the value | Assignment copies the reference |
| Often models a small value | Often models an entity or object with identity |
| Can contain value-type and reference-type fields | Can contain value-type and reference-type fields |

```csharp
Point first = new Point { X = 10, Y = 20 };
Point second = first;

second.X = 99;
Console.WriteLine(first.X);  // 10
Console.WriteLine(second.X); // 99
```

Assigning `first` to `second` copies the struct's fields. The two variables then hold separate struct values.

With a class, assignment copies a reference, so both variables can refer to the same object:

```csharp
class Coordinate
{
    public int X;
}

Coordinate firstCoordinate = new Coordinate { X = 10 };
Coordinate secondCoordinate = firstCoordinate;
secondCoordinate.X = 99;

Console.WriteLine(firstCoordinate.X); // 99
```

## 2. Value Semantics and Reference Fields

Copying a struct copies each field. A value-type field is copied as a value; a reference-type field is copied as a reference.

```csharp
class Address
{
    public string City { get; set; } = "";
}

struct CustomerInfo
{
    public int Id;
    public Address Address;
}

var original = new CustomerInfo
{
    Id = 1,
    Address = new Address { City = "Toronto" }
};

var copy = original;
copy.Id = 2;
copy.Address.City = "Ottawa";
```

`original.Id` remains `1`, because the integer field was copied. Both struct values hold a reference to the same `Address` object, so changing its `City` through either reference is visible through the other.

```text
Copy a struct
    -> value-type fields are copied
    -> reference-type fields copy their references
    -> referenced objects are not cloned automatically
```

## 3. `readonly struct`

A `readonly struct` expresses an immutable value: its instance state cannot be changed after construction through the struct's members.

```csharp
readonly struct EmployeeId
{
    public int Id { get; }

    public EmployeeId(int id)
    {
        Id = id;
    }
}

EmployeeId id = new EmployeeId(101);
// id.Id = 102; // Invalid: Id has no setter.
```

Use a readonly struct when its value should not change after creation. A readonly struct does not make objects referenced by its fields immutable; those objects can still be mutable.

```text
readonly struct -> value type with read-only instance state
```

---

## 4. `ref struct`

A `ref struct` is a value type with language-enforced restrictions designed to prevent unsafe escape of values tied to a limited lifetime or memory region. `Span<T>` is a well-known example.

```csharp
Span<int> numbers = stackalloc int[3];
numbers[0] = 10;
```

Because a `Span<T>` can refer to stack-allocated memory, the compiler restricts where it can be stored or used. The exact restrictions depend on the C# language version; in general, a ref struct cannot be boxed or stored in ordinary heap locations that could outlive the referenced memory. Newer language versions add specific permitted uses, so consult the language version's rules when relying on those features.

`ref struct` and `readonly struct` solve different problems:

```text
struct         -> ordinary value type
readonly struct -> read-only instance state
ref struct      -> restricted lifetime and memory usage
```

---

## 5. Choosing a Struct

Structs are a good fit when the type represents a value, copying it has clear value semantics, and its design avoids surprising shared mutable state. A struct can still contain references, so copying it does not necessarily deep-copy everything reachable from it.

## Quick Memory Sheet

> **Struct = value type.** Assigning a struct copies its fields; reference fields copy references, not the referenced objects.

```text
struct          -> value semantics
readonly struct -> read-only instance state
ref struct      -> special lifetime and memory-safety restrictions
```
