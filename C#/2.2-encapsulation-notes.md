# C# 2.2 - Encapsulation

> **Revision status:** Strong / Recalled

Encapsulation is the practice of controlling how an object's internal state and implementation are accessed or modified.

> Expose what outside code needs while protecting internal state and implementation details.

---

## 1. What Is Encapsulation?

```csharp
class BankAccount
{
    private decimal _balance;

    public decimal Balance
    {
        get
        {
            return _balance;
        }
    }

    public void Deposit(decimal amount)
    {
        if (amount > 0)
            _balance += amount;
    }
}
```

Outside code can read `account.Balance`, but cannot directly modify `_balance`. It must use the controlled operation `account.Deposit(5000)`.

```text
Outside code
     -> public interface
     -> validation and business rules
     -> internal state
```

---

## 2. Why Encapsulation Exists

Without encapsulation, any caller could put invalid data into an object's state:

```csharp
class BankAccount
{
    public decimal Balance;
}

account.Balance = -50000;
```

With encapsulation, the class owns its state and enforces its rules:

```csharp
public void Deposit(decimal amount)
{
    if (amount <= 0)
        return;

    _balance += amount;
}
```

Encapsulation is more than making fields private. It also hides implementation details and exposes a controlled public interface. The implementation can change without changing the public API.

## 3. Access Modifiers

C# provides these main access modifiers:

```text
public
private
protected
internal
protected internal
private protected
```

### `private`

`private` means that a member is accessible only within its containing type.

```csharp
class Employee
{
    private decimal _salary;

    public decimal GetSalary()
    {
        return _salary;
    }
}
```

Code inside `Employee` can use `_salary`; unrelated outside code cannot.

```text
private -> containing type only
```

### `public`

`public` means the member is accessible wherever the containing type and member are accessible.

```csharp
class Employee
{
    public string Name;
}

var employee = new Employee();
employee.Name = "Rahul";
```

Use `public` when a member is intentionally part of the class's public API.

```text
public -> broadly accessible
```

### `protected`

`protected` allows access from the containing class and derived classes.

```csharp
class Employee
{
    protected decimal _salary;
}

class Manager : Employee
{
    public void GiveRaise()
    {
        _salary += 5000;
    }
}
```

Outside code cannot access `_salary` directly through a `Manager` object.

```text
protected -> containing type + derived types
```

### `internal`

`internal` allows access throughout the same assembly. For practical purposes, an assembly is a compiled `.dll` or `.exe`.

```csharp
internal class PaymentService
{
    internal void ProcessPayment()
    {
    }
}
```

This is useful when implementation details should be available inside a library but hidden from consumers in other assemblies.

```text
internal -> same assembly
```

### `protected internal`

`protected internal` means **protected OR internal**. Access is allowed when either condition is satisfied:

1. The code is in the same assembly.
2. The code is in a derived class.

```csharp
class Parent
{
    protected internal int Value;
}

class Child : Parent
{
    public void Test()
    {
        Value = 10;
    }
}
```

An unrelated type in the same assembly can also access `Value`.

```text
protected internal -> protected OR internal
                   -> derived type OR same assembly
```

### `private protected`

`private protected` is more restrictive. It allows access from the containing type and from derived types in the same assembly.

```csharp
class Parent
{
    private protected int Value;
}

class Child : Parent
{
    public void Test()
    {
        Value = 10;
    }
}
```

A derived class in another assembly cannot access `Value`.

```text
private protected -> protected AND same assembly
```

---

## 4. Access Modifier Comparison

| Modifier | Same class | Derived, same assembly | Derived, different assembly | Unrelated, same assembly |
| --- | --- | --- | --- | --- |
| `private` | Yes | No | No | No |
| `protected` | Yes | Yes | Yes | No |
| `internal` | Yes | Yes | No | Yes |
| `protected internal` | Yes | Yes | Yes | Yes |
| `private protected` | Yes | Yes | No | No |
| `public` | Yes | Yes | Yes | Yes |

The combined modifiers are easiest to remember as:

```text
protected internal -> OR
private protected   -> AND
```

## 5. Properties and Encapsulation

Properties are commonly used to provide controlled access to internal state.

```csharp
class Employee
{
    private decimal _salary;

    public decimal Salary
    {
        get
        {
            return _salary;
        }
    }

    public void IncreaseSalary(decimal amount)
    {
        if (amount > 0)
            _salary += amount;
    }
}
```

Outside code can read `employee.Salary`, but it cannot directly modify `_salary`. It must call `IncreaseSalary`.

### `get; private set;`

A property can expose public read access while restricting writes to the class:

```csharp
class Employee
{
    public decimal Salary { get; private set; }

    public void IncreaseSalary(decimal amount)
    {
        if (amount > 0)
            Salary += amount;
    }
}
```

Outside code can read `Salary`, but cannot assign it directly.

### `init`

An `init` accessor allows a property to be assigned during object construction, including an object initializer, but not changed afterward by normal outside code.

```csharp
class Employee
{
    public string Name { get; init; }
    public int Age { get; init; }
}

var employee = new Employee
{
    Name = "Rahul",
    Age = 30
};

// employee.Name = "John"; // Invalid after initialization
```

`init` is useful for immutable or mostly immutable objects that still need convenient initialization.

## 6. Field, Property, and Methods Together

A strong encapsulation design keeps the field private and exposes controlled operations.

```csharp
class BankAccount
{
    private decimal _balance;

    public decimal Balance => _balance;

    public void Deposit(decimal amount)
    {
        if (amount > 0)
            _balance += amount;
    }

    public void Withdraw(decimal amount)
    {
        if (amount > 0 && amount <= _balance)
            _balance -= amount;
    }
}
```

Usage:

```csharp
var account = new BankAccount();

account.Deposit(1000);
account.Withdraw(300);

Console.WriteLine(account.Balance); // 700
```

This is not allowed:

```csharp
account._balance = 5000;
```

The only supported state changes are the controlled operations defined by the class.

---

## 7. Why `Deposit()` and `Withdraw()` Are `void`

```csharp
public void Deposit(decimal amount)
```

Breakdown:

```text
public         -> access modifier
void           -> return type
Deposit        -> method name
decimal amount -> parameter
```

The method accepts a `decimal` amount and returns nothing. If a method needs to return a value, the return type appears before its name:

```csharp
public decimal GetBalance()
{
    return _balance;
}
```

Here, `decimal` is the return type.

## 8. Encapsulation and Business Rules

Encapsulation lets a class enforce business rules at the point where state changes:

```csharp
public void IncreaseSalary(decimal amount)
{
    if (amount <= 0)
        throw new ArgumentException("Amount must be positive.");

    if (amount > 100000)
        throw new InvalidOperationException("Increase is too large.");

    _salary += amount;
}
```

Outside code asks the object to perform an operation instead of manipulating `_salary` directly. The object owns its state and controls how that state changes.

## 9. Real-World Example

```csharp
class BankAccount
{
    private decimal _balance;

    public decimal Balance => _balance;

    public void Deposit(decimal amount)
    {
        if (amount <= 0)
            throw new ArgumentException("Amount must be positive.");

        _balance += amount;
    }

    public void Withdraw(decimal amount)
    {
        if (amount <= 0)
            throw new ArgumentException("Amount must be positive.");

        if (amount > _balance)
            throw new InvalidOperationException("Insufficient balance.");

        _balance -= amount;
    }
}
```

Here:

```text
_balance -> private internal state
Balance  -> public controlled read access
Deposit  -> controlled modification
Withdraw -> controlled modification with validation
Class    -> owns and protects its state
```

## 10. Common Misconceptions

### Encapsulation only means making fields private

Private fields are one mechanism, but encapsulation also protects state, controls access, hides implementation details, and exposes a clear public interface.

### `protected` means public access through a child object

No. It permits access from derived-class code; it does not make the member publicly accessible.

### `internal` means private

No. `internal` allows access from anywhere in the same assembly.

### `protected internal` means both protected and internal

For C#, remember that `protected internal` is an OR relationship. Either protected access or same-assembly access is enough.

### `private protected` means private OR protected

No. It is an AND relationship: derived class and same assembly are required.

### A public property means its field is public

No. A property can be public while its backing field remains private:

```csharp
private decimal _salary;
public decimal Salary => _salary;
```

### A derived class can access every base member

No. A derived class cannot directly access private members of its base class.

## Core Mental Model

```text
Encapsulation
      -> protect internal state
      -> expose controlled interface
      -> enforce rules
```

Access modifiers:

```text
private
    -> containing type only

protected
    -> containing type + derived types

internal
    -> same assembly

protected internal
    -> protected OR internal

private protected
    -> protected AND same assembly

public
    -> broadly accessible
```

Properties and methods:

```text
private field
      -> public property
      -> controlled read access

private field
      -> public method
      -> controlled modification
```
