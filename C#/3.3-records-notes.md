# C# 3.3 - Records

> **Revision status:** Strong / Recalled

A `record` is designed for data-oriented objects. Records provide value-based equality, so objects with the same record type and equal data can compare as equal.

```csharp
record Person(string Name, int Age);
```

A normal `record` (also called a record class) is a reference type.

---

## 1. Class vs Record

An ordinary class uses reference equality by default. Two different class instances are unequal unless the class defines different equality behavior.

```csharp
class PersonClass
{
    public string Name { get; set; } = "";
    public int Age { get; set; }
}

var firstClass = new PersonClass { Name = "Rahul", Age = 25 };
var secondClass = new PersonClass { Name = "Rahul", Age = 25 };

Console.WriteLine(firstClass == secondClass); // False
```

Records generate value-based equality using their data:

```csharp
record Person(string Name, int Age);

Person first = new("Rahul", 25);
Person second = new("Rahul", 25);

Console.WriteLine(first == second); // True
```

```text
record -> reference type with value-based equality
```

Do not confuse reference type with reference equality. They describe different things.

---

## 2. Positional Records

A positional record declares its data in the parameter list. The compiler generates a constructor and corresponding properties.

```csharp
record Person(string Name, int Age);

Person person = new("Rahul", 25);
Console.WriteLine(person.Name);
Console.WriteLine(person.Age);
```

The equivalent record can be written with explicitly declared properties:

```csharp
record Person
{
    public string Name { get; init; } = "";
    public int Age { get; init; }
}
```

For a positional record class, the generated properties use `init` accessors, so they can be set during initialization but not normally reassigned afterward.

---

## 3. `get`, `set`, and `init`

```text
get  -> read a property
set  -> assign or change a property
init -> assign a property during object initialization
```

```csharp
class MutablePerson
{
    public string Name { get; set; } = "";
}

var person = new MutablePerson { Name = "Rahul" };
person.Name = "Amit"; // Allowed because Name has a set accessor.
```

An `init` property can be assigned when the object is created:

```csharp
record Person
{
    public string Name { get; init; } = "";
}

Person person = new Person { Name = "Rahul" };
// person.Name = "Amit"; // Not allowed after initialization.
```

---

## 4. The `with` Expression

For a record class, `with` creates a new record based on an existing one and applies the specified changes. The original is unchanged.

```csharp
record Person(string Name, int Age);

Person original = new("Rahul", 25);
Person updated = original with { Age = 26 };
```

```text
original -> Rahul, 25
updated  -> Rahul, 26
```

```text
with -> copy existing record -> apply changes -> produce a new record
```

---

## 5. Immutability and Shallow Immutability

A record is not automatically immutable. A record with a `set` property can still be changed:

```csharp
record Person
{
    public string Name { get; set; } = "";
}
```

Positional record-class properties use `init`, but this only prevents reassignment of the property after initialization. It does not make referenced objects deeply immutable.

```csharp
record Person(string Name, Address Address);

class Address
{
    public string City { get; set; } = "";
}

Person person = new("Rahul", new Address { City = "Delhi" });

// person.Address = new Address(); // Not allowed after initialization.
person.Address.City = "Mumbai"; // Allowed: the Address object is mutable.
```

`init` protects the property assignment, not necessarily the state of the object the property refers to.

---

## 6. `record struct`

A record class is a reference type. A `record struct` is a value type. Both generate value-based equality.

```csharp
record Person(string Name);
record struct Point(int X, int Y);
```

```text
record        -> reference type, value-based equality
record struct -> value type, value-based equality
```

---

## 7. Assignment: Record vs Record Struct

Assigning a record-class variable copies the reference. Both variables refer to the same record object:

```csharp
record Person(string Name);

Person first = new("Rahul");
Person second = first;
```

Assigning a record struct copies its value. The variables hold separate copies:

```csharp
record struct Point(int X, int Y);

Point first = new(10, 20);
Point second = first;
```

---

## 8. Record Structs with Reference-Type Members

Copying a record struct copies its fields. If a field contains a reference, that reference is copied too. The copied structs can therefore refer to the same referenced object.

```csharp
record struct Person(string Name);

Person first = new("Rahul");
Person second = first;
```

Both `Name` properties refer to the same string object. Since strings are immutable, that shared reference cannot be used to change the string contents.

---

## 9. `readonly record struct`

A `readonly record struct` is a value type with value-based equality whose state cannot be directly changed after creation.

```csharp
readonly record struct Point(int X, int Y);

Point original = new(10, 20);
// original.X = 50; // Not allowed.

Point changed = original with { X = 50 };
```

The `with` expression produces a new value; it does not modify `original`.

```text
original -> {10, 20}
changed  -> {50, 20}
```

---

## 10. Quick Memory Sheet

```text
class                   -> reference type; reference equality by default
record                  -> reference type; value-based equality
record assignment       -> copies the reference
struct                  -> value type
record struct           -> value type; value-based equality
readonly record struct  -> value type; value-based equality; no direct state mutation
positional record       -> concise constructor and generated properties
init                    -> assign during initialization
with                    -> create a modified copy; preserve the original
```

Records are not automatically deeply immutable. In particular, `init` does not make mutable objects referenced by a record immutable.
